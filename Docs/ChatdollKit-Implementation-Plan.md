# ChatdollKit 参考研究与从零实现方案

研究日期：2026-09-19。本文是设计方案与源码研究记录，目前尚未安装模型或完成性能测试。

## 一、目标与已确认条件

从零搭建 Windows 3D 桌面助手，借鉴 ChatdollKit 的架构，自行实现会话、语音调度、角色表现和桌面交互。

- 第一版必须完全离线运行，模型和依赖提前准备好，运行时不自动下载。
- 目标设备为用户当前电脑，显卡为 NVIDIA GeForce RTX 3080，显存 10GB。
- 当前工程使用 Unity 6000.3.5f2 和 URP，业务脚本目录基本为空。
- 工程存在第三方组件目录和生成的 C# 工程引用，但这些不能证明依赖已实际安装。

## 二、推荐技术方案

自行实现应用逻辑，复用成熟的角色加载、口型、语音识别、语音合成和模型推理组件。第一版不包含训练大模型或重写 VRM 导入器。

| 部分 | 第一版建议 | 需要验证的内容 |
| --- | --- | --- |
| 应用 | 现有 Unity 6.3 + URP | Windows 打包与角色材质兼容性 |
| 角色 | UniVRM + 一个固定 VRM 模型 | 表情、动画、材质及模型版本 |
| 对话 | llama.cpp + Qwen2.5-3B-Instruct GGUF Q4 | 中文效果、显存、首段输出延迟 |
| 语音识别 | whisper.cpp + 多语言 small 模型作为候选 | 中文识别准确率和耗时 |
| 语音合成 | sherpa-onnx + 中文 VITS 模型作为候选 | 中文音质、合成速度及模型许可证 |
| 口型 | uLipSync | 根据实际播放音频驱动嘴型 |
| 数据 | 配置文件 + SQLite | 设置、会话和记忆的保存与删除 |

以上是待实测的起始候选。优先让对话模型使用显卡，语音部分先测试 CPU 运行，再根据实际表现分配资源。Unity 渲染、模型权重和上下文缓存会共同占用显存；是否升级到 7B，需要在角色渲染开启时实测。

## 三、整体架构

```text
麦克风 -> 按键录音 -> 本地语音识别 -> 会话管理 -> 本地大模型
                                      ↑             ↓
                                    历史记录      流式分句
                                                    ↓
角色口型、表情 <- 音频播放队列 <- 本地语音合成
                        ↓
                      同步字幕
```

Unity 负责交互和角色表现，本地推理放在独立进程中，通过仅监听本机的接口通信。应用负责启动、检查和关闭进程，最终用户不需要手动启动多个服务。

自行管理会话状态、取消操作、回答分句、播放队列、角色动作映射和设置。用小型接口隔离不同推理引擎，每轮对话和每个语音片段使用明确编号，避免迟到结果恢复已经取消的音频，或覆盖新一轮对话。

## 四、分阶段实施与验收

| 阶段 | 实现内容 | 验收标准 |
| --- | --- | --- |
| 1. 基础验证 | 加载角色，本地文字对话，分别跑通识别和合成 | 断网启动可用，Unity 与推理同时运行不耗尽显存 |
| 2. 文字驱动角色 | 流式回答、分句朗读、口型和字幕 | 连续对话正常，语音顺序正确，停止后不播放旧回答 |
| 3. 完整语音对话 | 按键说话、中文识别、上下文和设备异常恢复 | 连续完成多轮语音对话，静音或设备异常不导致卡死 |
| 4. 桌面体验 | 透明、置顶、拖动、穿透切换、托盘和设置 | Windows 打包后功能正常，可随时恢复操作窗口 |
| 5. 自然交互 | 自动检测说话、语音打断、表情和动作调度 | 不将自身播放的声音反复识别成用户输入 |
| 6. 记忆与能力 | 会话摘要、长期记忆和受限的本地工具 | 记忆可查看和删除，工具调用范围可控 |

有 Unity/C# 经验的单人开发，可先按 4～6 周规划前四阶段的原型预算。这是粗略估计，回声处理、模型效果、资源竞争和发布打包可能增加时间。

第一步应制作基础验证场景：一个角色、一个本地对话模型、一套中文识别与合成。记录显存占用、识别耗时和首句出声延迟，再确定最终模型配置。

## 五、主要难点

1. **流式分句与延迟**：按合理的标点和长度切分回答，避免读出不完整标签、拆坏数字或使语音过于零碎。播放当前句时准备下一句，并限制预取并发数和队列长度。
2. **完整取消**：停止时同时取消生成、待合成任务、播放、字幕和角色动作，丢弃旧会话的迟到结果。
3. **回声与误触发**：自动打断可能把扬声器声音当成用户输入。先采用按键说话或耳机，再单独验证 Windows 录音和回声消除。
4. **角色兼容性**：VRM 版本、表情名称、动画映射、材质和口型控制可能不同，先验证一个固定模型。
5. **打断后的历史记录**：明确处理只播放了一部分的回答，避免把用户尚未听到的内容当作已经完成的对话。
6. **异常恢复**：处理本地进程退出、推理超时、模型缺失、麦克风断开、组件禁用和不支持的音频格式，避免会话一直停留在处理中。

## 六、已核实的 ChatdollKit 设计

- ChatdollKit 是面向可语音交互的 3D 助手的 Unity 开发工具包。官方说明涵盖大模型接入、语音识别与合成、上下文管理、表情、动画、眨眼、口型、多模态输入和工具调用。读取的说明文档将 0.8.16 列为最新介绍版本，本次没有独立确认最新发布版本。[官方说明](https://github.com/uezo/ChatdollKit/blob/master/README.md)
- 本次检查的源码提交为 `e694f443247e0a322ea5f0b5dc4a36838defc20e`，以下源码链接固定到该版本。[源码目录](https://github.com/uezo/ChatdollKit/tree/e694f443247e0a322ea5f0b5dc4a36838defc20e)
- `DialogProcessor` 选择 `ILLMService`、发现 `ITool` 组件、构建提示词并启动生成。生成流尚未结束时就可以解析和呈现回答；同时维护对话状态、每轮取消令牌、停止回调和处理编号。[对话处理源码](https://github.com/uezo/ChatdollKit/blob/e694f443247e0a322ea5f0b5dc4a36838defc20e/Scripts/Dialog/DialogProcessor.cs)
- `LLMContentProcessor` 将流式回答拆成内容项，准备后按队列顺序呈现。流解析与呈现循环采用独立的异步操作。[内容处理源码](https://github.com/uezo/ChatdollKit/blob/e694f443247e0a322ea5f0b5dc4a36838defc20e/Scripts/LLM/LLMContentProcessor.cs)
- `AIAvatar` 将内容项转换为 `AnimatedVoiceRequest`，提前请求语音合成，然后调用 `ModelController.AnimatedSay`。停止回调会立即停止说话，并将麦克风策略、消息窗口与对话生命周期连接起来。[角色调度源码](https://github.com/uezo/ChatdollKit/blob/e694f443247e0a322ea5f0b5dc4a36838defc20e/Scripts/AIAvatar.cs)
- 官方说明列出 Burst、UniTask（测试版本 2.5.4）、uLipSync（测试版本 3.1.0）、UniVRM（0.127.2）、独立的 ChatdollKit VRM 扩展和 Newtonsoft JSON。可选的 Silero 语音活动检测需要 ONNX 运行时、模型和扩展。这些是上游文档列出的配置，并非已经验证适合当前 Unity 6 工程的版本组合。[安装与语音检测说明](https://github.com/uezo/ChatdollKit/blob/master/README.md)
- 官方说明对其文档采用的 UniVRM 配置提出了可编程渲染管线（SRP）使用警告，不能据此认定所有新版 UniVRM 都不支持 URP。当前工程需要结合选定组件版本和实际模型验证材质与着色器。[安装说明](https://github.com/uezo/ChatdollKit/blob/master/README.md)
- 官方说明包含语音打断和 WebSocket 流式语音识别。Unity 内置麦克风不提供回声消除；文档列出了 iOS、Android 和 macOS 原生麦克风集成，但不能据此确认 Windows 回声消除方案已经具备。[语音监听说明](https://github.com/uezo/ChatdollKit/blob/master/README.md)
- ChatdollKit 使用 Apache-2.0 许可证。若复用和分发其代码，需要保留许可证及适用声明，标注修改，并在存在适用 NOTICE 时保留相关归属信息。模型、动作、声音和其他依赖需要分别检查许可证。[许可证](https://github.com/uezo/ChatdollKit/blob/master/LICENSE)
